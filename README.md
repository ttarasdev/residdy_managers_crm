# Residdy Managers CRM

Менеджерський фронтенд на Next.js, TypeScript, SCSS, TanStack Query, Tiptap і Lucide. Світла та темна теми, десктопний інтерфейс від 1080px.

```bash
npm install
npm run dev
```

Задайте `NEXT_PUBLIC_API_URL` у `.env.local` (наприклад, `http://localhost:3001`). Використовуйте адресу саме API; запити авторизуються bearer-токеном. Бек повинен дозволяти origin фронтенду через CORS.

## Можливості

- Вхід, підтвердження нового акаунта, відновлення пароля, профіль, зміна e-mail/пароля, вихід.
- Меню за ролями, dashboard із кількістю записів з API, універсальні таблиці, фільтри, пагінація, сторінки записів і форми операцій.
- Справи: створення, редагування, копіювання; вкладені етапи й завдання з додаванням, видаленням та зміною порядку. Інструкції з текстовими й фото-блоками, типи справ, шаблони нагадувань.
- Акаунти, користувачі, спеціалісти, менеджери та ролі; статуси й операції, які дозволяє бек.
- Блог, категорії, публікація за розкладом; типи, змінні та шаблони документів.
- Публічні й приватні файли, варіанти зображень, завантаження з форми, скачування та перегляд приватних зображень з авторизацією.
- Бронювання, категорії консультацій, активні консультації, відгуки; партнери, компанії, банери й модерація.
- Промокоди, умови консультацій, дозволені акаунти та історія використання.
- Підписки: версії планів, ціни/продукти провайдерів, пробний період і dev-симуляції подій.
- Юридичні документи: актуальні PDF, завантаження чернеток, версії та публікація.
- Журнал перевірених платежів і п’ять аналітичних звітів із фільтрами UTC та пагінацією.
- Поштові кампанії, аудиторії, вкладення, CID-зображення, розклад, скасування, прогрес; сповіщення, нагадування й ручні операції черг.

Інтерфейс використовує 51 ресурс та схеми 232 операцій наявної менеджерської API-бібліотеки. Спільні операції не копіюються в десятки окремих форм. Клієнтські маршрути користувачів/спеціалістів (оплата, власні слоти, особисті документи тощо) не переносяться в CRM.

## Структура

- `src/api` — типізовані HTTP-методи й DTO нового бека.
- `src/components/ui` — кнопки, статуси й стани завантаження/помилок.
- `src/components/form-components` — повторно використовувані контейнери, поля, списки вибору, модальні вікна й редактор.
- `src/components/layout-components` — оболонка, меню, хедер.
- `src/features/crm` — каталог розділів, схеми форм, універсальні таблиці/сторінки/дії, окремий робочий простір справ.
- `src/shared/styles` — токени двох тем і спільні SCSS-міксіни.
- `src/shared/auth`, `hooks`, `providers`, `query` — сесія та кеш.
- `src/app/(public)` і `(private)` — маршрути App Router.

Докладніше: [архітектура CRM](src/features/crm/README.md), [API](src/api/README.md), [сесія](src/shared/README.md), [бібліотека форм](src/components/form-components/README.md).

## Перевірки

```bash
npm test
npm run lint
npm run format:check
npm run build
npm run api:schema
npx playwright install chromium
npm run test:browser
```

`api:schema` регенерує схеми форм після зміни API-типів. `npm test` перевіряє типи, транспорт, контракти, авторизацію, доступи, форми й перетворення даних CRM зі змоканим API. Браузерні тести запускають окрему production-збірку з API-заглушкою та перевіряють навігацію, форми, файли, порядок і ролі. Реальні листи та черги під час тестів не запускаються. Після браузерних тестів `npm run build` перебудовує production-застосунок з вашим `.env`.

Формат: 4 пробіли, один порожній рядок між блоками, SCSS Modules без Tailwind. Довідкові `src/shared/old-front`, `new-back` і `new-back-2` не змінюються і не потрапляють у збірку.

## Межі поточного бека

- `marketolog` бачить партнерський розділ у меню, але довідковий бек дозволяє його операції лише `admin`/`manager`. Без відповідної серверної ролі дані та дії недоступні; фронт не обходить цей контроль.
- `writer` — роль розсилок; `admin` не є автоматично будь-якою іншою роллю.
- Приватні assets/variants мають списки з пагінацією та серверною перевіркою видимості; CRM показує їх за бакетами.
- HTML листів редагується як HTML зі збереженням початкової верстки. Ізольований перегляд блокує скрипти й зовнішні ресурси; CID-зображення остаточно підставляє поштовий бек.
- Неактивні категорії консультацій читаються через менеджерський список; за відсутності фільтра ID їх пошук може потребувати кількох сторінок API.

Адаптація під другу версію бека: [зміни й обмеження](src/api/BACKEND-2.md).

## Реклама в застосунку

`Komunikacja → Reklamy w aplikacji` (`/main/resources/app-announcements`) — тільки роль `writer`, включно із завантаженням картинок. Є створення, редагування, розклад, вимкнення та видалення. Чотири мовні картинки можна завантажити з форми або вибрати з `system_files`; доступний попередній перегляд. Одну картинку можна використати для кількох мов. Тип переходу визначає поля форми: без переходу, HTTPS-сайт, екран чи конкретний запис.

Початок включний, кінець виключний; дати вводяться у часовому поясі браузера. Увімкнені періоди не можуть перетинатися — конфлікт показується з API. Внутрішня назва не відображається користувачам; текст реклами міститься на картинках. Видалення оголошення залишає асети в бібліотеці.

## Медіабібліотека й підписи

Візуальні бібліотеки, правила вибору іконок/фото та підписи листів описані в [MEDIA_LIBRARY.md](MEDIA_LIBRARY.md). Інструкції використовують `headerVariantId`; старі обкладинки підтримуються для читання. Нові операції входять до `npm run api:schema`.

## Firmy partnerów

Administrator tworzy firmę w sekcji firm partnerów, wybierając istniejącego partnera. Tylko administrator może edytować dane i zdjęcia, publikować/archiwizować firmę oraz zatwierdzać i uruchamiać banery. Panel partnera ma podgląd firmy bez edycji. Nowy baner i zmiany banera wymagają moderacji.

Podgląd reklamy partnera: `PartnerBannerDetails.tsx` prezentuje format mały/duży, cztery wersje językowe, status, link i statystyki. `banner-actions.ts` dobiera akcje do statusu (moderacja → aktywacja → zakończenie); po operacji dane są odświeżane przed zamknięciem formularza.
