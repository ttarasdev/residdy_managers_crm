# Медіабібліотека та підписи листів

## Де шукати в CRM

- **Biblioteka → Ikony i pliki publiczne** (`/main/icons`): іконки та системні картинки.
- **Biblioteka → Zdjęcia** (`/main/resources/private-variants`): вкладки з обкладинками інструкцій, фото блоків, блогом, аватарами та фото партнерів.
- **Biblioteka → Pliki prywatne** (`/main/resources/private-assets`): особисті файли, шаблони документів, документи користувачів, файли консультацій. Бек фільтрує записи за доступом ще до пагінації.
- **Komunikacja → Podpisy e-mail** (`/main/resources/mail-signatures`): спільні для ролі `writer` підписи. Поле **Podpis e-mail** є в прямому листі та кампанії. Можна залишити без підпису.

## Правила вибору

| Поле | Бакет | Вибір із бібліотеки | Завантаження у формі |
| --- | --- | --- | --- |
| Іконки | `icons`, public asset | Так, темні плитки в обох темах | Ні |
| Обкладинка інструкції | `instruction_headers`, private variant | Так, широкі прев’ю | Ні |
| Фото блоку інструкції | `instruction_images`, private variant | Так | Так |
| Фото поста | `blog_images`, private variant | Ні | Так, нове зображення |
| Лого, фото та банери партнерів | `partner_logos`, `partner_main`, `partner_adv` | Так, якщо API має поле ID | Завантаження через відповідний API |
| Особисті вкладення менеджера | `manager_files`, private asset | Лише доступні власнику/адміну | Так |

Універсальний picker сам передає потрібний бакет. Форма не пропонує вручну вводити ID, власника або видимість файлу. Іконки завантажують централізовано на сторінці бібліотеки. Бек додатково перевіряє нові бакети обкладинок, блоків і блогу.

Завантаження створює файл до збереження батьківської форми. Якщо форму скасувати, файл залишається в бібліотеці; його можна видалити, якщо він не використовується іншими записами. Існуючі зовнішні ключі захищають прив’язані файли від видалення.

## Структура

- `src/features/crm/media.ts` — відповідність поля, типу медіа, бакета й дозволених способів вибору.
- `src/components/media-components/MediaPicker.tsx` — вибір і завантаження.
- `MediaGrid.tsx` — спільна сітка з пагінацією.
- `MediaThumbnail.tsx` — публічний SVG/растр або авторизоване прев’ю приватного файлу.
- `MediaUpload.tsx` — спільний upload із фіксованим бакетом.
- `src/features/crm/components/MediaLibrary.tsx` — вкладки бібліотеки, перегляд, завантаження, улюблені й видалення.
- `SchemaForm.tsx` використовує picker для медіаполів. `RecordDetails.tsx`, `DataTable.tsx` і блоки інструкції використовують ті самі прев’ю.
- `MailSignaturePreview.tsx` — попередній перегляд редагованого підпису та збереженої копії кампанії.

## Сумісність

Інструкція тепер створюється з `headerVariantId`. Старий `headerIconId` залишається nullable у відповіді для попередніх записів; це **public asset**, його не можна трактувати як ID variant. Старі файли фізично не переміщуються. При заміні обкладинки вибирається новий variant із `instruction_headers`.

Старе фото поста або блоку можна залишити під час редагування тексту. При заміні зображення потрібен правильний новий бакет. Для блогу вже використаний іншим постом variant відхиляється.

Підпис кампанії зберігається у `signatureSnapshot`. Зміна шаблону не переписує існуючу кампанію; звичайне редагування теми листа також не оновлює копію підпису. Інший вибір підпису оновлює її, порожній вибір видаляє. Після планування кампанія не редагується. Лого вкладається як CID PNG, а не як залежність від зовнішньої адреси картинки.

Актуальний бек: `../residdy_backend`. Міграції 025–026 та початковий підпис Residdy застосовані до окремої development-бази. Production не змінювалася. Мобільний клієнт має read API й типи в `../residdy_mobile/src/api/content`; портал партнерів/спеціалістів отримав оновлені типи бакетів.
