# CRM

## Один каталог, спільні компоненти

`catalog.ts` описує назву, адресу, групу, ролі та колонки ресурсу. Його використовують Sidebar, dashboard, breadcrumb і перевірка приватного маршруту. `labels.ts` містить підписи операцій, полів та enum-значень.

`generated/operations.ts` генерується з активних `*.api.ts` і DTO через TypeScript checker. Схема містить назви/типи аргументів, обов’язковість, enum-значення, вкладені поля та масиви. Виклик делегується існуючому API-методу; другий HTTP-клієнт не створюється. Генератор не виводить обмеження class-validator. `field-rules.ts` містить UI-обмеження нових DTO (ліміти планів, пробний період, PDF), спільні для полів і перевірки перед запитом. Бізнес-умови й доступ остаточно перевіряє бек.

```bash
npm run api:schema
```

Генерація потрібна лише при зміні API-типів. Згенерований файл не редагуйте вручну. Маршрути ресурсу містять тільки `ResourcePage` з його ID; для додаткових ресурсів є `/main/resources/[resource]` і `/[id]`.

## Сторінки й форми

- `ResourcePage`: список або запис, фільтри API, серверна пагінація, локальний пошук на поточній сторінці, дії з перевіркою ролей.
- `DataTable`: колонки за шляхом поля, статуси, форматування дат і посилання на деталі.
- `RecordDetails`: поля запису, вкладені дані, безпечний перегляд HTML, Tiptap JSON і фото.
- `ActionDialog`: форма операції, перевірка обов’язкових значень, стан запиту, результат, завантаження Blob, інвалідація кешу. Мутації виконуються лише після submit; видалення має підтвердження.
- `SchemaForm`: текст/число/дата/enum, об’єкти, масиви, файли, редактор. Пов’язані ID вибираються зі списку API з пагінацією. Приватні файли можна завантажити у вкладеному діалозі.
- `CaseWorkspace`: етапи, завдання та блоки інструкцій. Порядок змінюється бекендовим `reorder`, дочірні завдання завантажуються при розкритті етапу.
- `Profile`: поточний менеджер/акаунт і безпека.

`data.ts` відокремлює response від request: зв’язки `categories` → `categoryIds`, збережені `audienceJson` → `audience`, числові значення й boolean-фільтри. Поля відповіді, яких немає в DTO, не відправляються назад.

`read-resource.ts` містить два винятки до загального читання: повний менеджерський профіль спеціаліста та неактивна категорія консультацій читаються через list, бо публічні detail endpoints не підходять для цих сценаріїв.

## Кеш і доступ

Ключі починаються з `['crm', resource]`, решта містить метод, ID і фільтри. Запити отримують AbortSignal, кеш належить поточній сесії. Після мутації інвалідуються CRM і довідники форм; повторної автоматичної відправки мутації немає.

Доступ сторінки й операції перевіряються окремо. Порожні ролі операції означають спільний endpoint, а не публічну CRM-сторінку. Дозволи сервера залишаються вирішальними. Операції черг `tick` і `build` ніколи не запускаються при відкритті сторінки.

## Стилі

`tokens.scss` задає всі кольори тем. `surface.mixins` — панелі й компонування; `control.mixins` — контролери й кнопки; `form.mixins`, `modal.mixins`, `page.mixins` — повторювані шаблони. `crm.module.scss` спільний для таблиць, деталей, форм і вкладених колекцій. Візуальну зміну робіть тут, а не в кожному маршруті.

## Доповнення v2

`AnalyticsPage` відкриває один із п’яти звітів, передає дати YYYY-MM-DD у UTC й відображає вкладені агрегати через спільні таблиці. Дані production/sandbox/dev та валюти не сумуються. Кінець діапазону виключний; максимальний діапазон — 366 днів.

`TrialSettings` завантажує налаштування пробного періоду й передає їх у спільну форму редагування. `RecordActions` дає вибір дії та перегляд запису для ресурсів без detail endpoint, зокрема версій юридичних документів. Поточний юридичний документ відкривається за `code`, а файл завантажується за `versionId`; ці значення не взаємозамінні.
