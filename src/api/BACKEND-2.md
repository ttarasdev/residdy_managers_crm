# Адаптація до new-back-2

Джерело контрактів — довідкова копія `src/shared/new-back-2`. Її порівняно з `new-back`; обидві копії залишено без змін і виключено зі збірки, форматування та тестової компіляції.

## Додані менеджерські можливості

| Ресурс             | Маршрути нового API                                                              | Інтерфейс                                                            |
| ------------------ | -------------------------------------------------------------------------------- | -------------------------------------------------------------------- |
| Плани              | GET/POST `/subscription-plans`, GET `/:id`, PATCH `/:id/retire`                  | Список, деталі, нова версія плану, виведення з доступних             |
| Пробний період     | GET/PATCH `/subscription-plans/trial-settings`                                   | Завантажені налаштування, вибір плану, 1–90 днів, увімкнення         |
| Ціни               | GET/POST `/subscription-prices`, GET `/:id`, PATCH `/:id/retire`                 | Зв’язки планів із продуктами Apple/Google/dev                        |
| Симуляція          | POST `/user-subscriptions/dev/:userId/events`                                    | Явна дія адміністратора, користувач, тип події, eventId, ціна        |
| Юридичні документи | GET `/legal-documents`, GET `/:code`, GET `/versions/:id/file`                   | Актуальні версії, PDF, перехід до керування версіями                 |
| Версії PDF         | GET/POST `/legal-document-versions/:code`, POST `/:id/publish`, GET `/:id/draft` | Вибір документа, чернетка PDF до 2 МБ, публікація, скачування        |
| Платежі            | GET `/payment-ledger`                                                            | Фільтри періоду, середовища, провайдера, валюти, типу операції       |
| Аналітика          | GET `/analytics/{overview,subscriptions,consultations,usage,revenue}`            | П’ять звітів, UTC-фільтри, день/місяць, серверна пагінація агрегатів |
| Бронювання         | POST `/consultation-bookings/:id/retry-operations`, PATCH `/:id/cancel-by-admin` | Підтвердження дії адміністратора; повторна обробка/скасування        |

Додано 26 операцій: усього 217 у 49 ресурсах. Нові адміністративні розділи доступні ролі `admin`; менеджер продовжує читати бронювання, але не може запускати нові адміністративні дії.

## Змінені дані

- Бронювання: статуси зустрічі та повернення, провайдер/час оплати, строки відмови, первинна дата, revision, зафіксований план і знижка підписки.
- Приватний файл: `expiresAt`, `fileDeletedAt`. Видалений фізичний файл може повертати 410 — це помилка конкретного запиту, а не причина завершувати сесію.
- Документ користувача: `subscriptionPlanId` у вкладених типах відповіді; клієнтські маршрути генерації не додавались.
- Акаунт: опційні `legalVersionIds` у DTO.
- Нові buckets: `legal_documents` та `legal_document_drafts`. Публікація правових PDF відбувається через спеціальний API: загальне завантаження public-assets не пропонує зарезервований `legal_documents`.

## Семантика й межі

- Новий `UserSubscriptionGuard` перевіряє тільки акаунти `USERS`. Менеджерський акаунт не потребує користувацької підписки для роботи CRM.
- План не редагується на місці: POST з тим самим `code` створює нову версію й прибирає попередню з доступних. Значення лімітів `-1` означають безліміт; `retentionMonths = 0` заборонено.
- API списків планів і цін повертає лише `available: true`. Виведений запис залишається доступним через його ID.
- Ціни — це конфігурація продуктів провайдера. Бек не приймає довільну грошову ціну в цьому DTO; фронт не додає такого поля.
- Симуляції працюють лише за `NODE_ENV=development` і `SUBSCRIPTIONS_DEV_ENABLED=true` на бекові. `eventId` забезпечує повторюваність того самого запиту. Жодні події автоматично не надсилаються.
- Юридичний документ ідентифікується `code`, версія — числовим ID. Оригінальне `versionId` з відповіді використовується при скачуванні PDF. Валідність PDF і можливість публікації перевіряє сервер.
- Аналітика використовує UTC та виключний `to`, максимум 366 днів; кеш бека — 120 секунд. Неповна історія й дані dev позначаються. Один звіт завантажується за раз.
- Суми журналу — рядки з цілими числами в найменших одиницях валюти. Великі значення не перетворюються на JavaScript number. Production, sandbox, dev і різні валюти показуються окремо. Бек наразі повідомляє, що платіжні адаптери не налаштовані.
- Потрібні міграції та початкові записи нового бека: плани/налаштування пробного періоду, юридичні документи. CRM показує помилку API, якщо вони відсутні.
- Партнерські права `marketolog` і розбіжність `writer`/`sender` у частині старих контролерів довідкового бека не змінені цією версією.

Не додані в менеджерське меню особисті покупки, checkout/verify-purchase, власна історія й квоти підписки, погодження документів від імені користувача, перенесення/оплата його консультації. У v2 для них немає відповідних менеджерських маршрутів.

## Перевірка

`npm test` перевіряє контракти нових маршрутів, multipart PDF, розділення code/versionId, обмеження полів, enum і точність сум. `npm run test:browser` перевіряє форми планів/цін, налаштування trial, публікацію та скачування PDF, аналітику й нові дії бронювання зі змоканим API. Реальних публікацій, листів, повернень чи симуляцій під час розробки не виконували.
